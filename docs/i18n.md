# Internationalisation (i18n)

Translation, locale context, and currency formatting.

---

## Stack

| Concern | Solution |
|---|---|
| Translated messages | `nestjs-i18n` + JSON translation files |
| Locale detection | `Accept-Language` header → AsyncLocalStorage |
| Validation errors | `I18nValidationPipe` + `I18nValidationExceptionFilter` |
| Currency formatting | `src/common/utils/currency.utils.ts` (pure, no deps) |

---

## Translation files

```
src/i18n/
├── en/
│   └── common.json   ← English (default fallback)
└── fr/
    └── common.json   ← French
```

Add more locales by creating new directories: `src/i18n/de/common.json`, etc.

`nest-cli.json` is configured to copy these files into `dist/i18n/` during builds.

### Using translations in a service

```typescript
import { I18nService } from 'nestjs-i18n';

constructor(private readonly i18n: I18nService) {}

// Translate a key
const msg = this.i18n.t('common.auth.loginSuccess');

// With interpolation
const err = this.i18n.t('common.storage.tooLarge', { args: { max: 50 } });

// Explicit locale
const fr = this.i18n.t('common.auth.loginSuccess', { lang: 'fr' });
```

### Adding a translation key

1. Add the key to `src/i18n/en/common.json`
2. Add matching keys to every other locale file (e.g. `fr/common.json`)
3. Use it via `i18n.t('common.your.key')`

## Locale detection

Locale is resolved on every request in this order:

1. **AsyncLocalStorage** — set by `AsyncStorageMiddleware` from the `Accept-Language` header
2. **Query parameter** — `?lang=fr`
3. **`Accept-Language` header** — standard browser/API header
4. **Fallback** — `'en'`

Only locales with a translation directory are recognised; unknown locales fall back to `en`.

### Reading locale anywhere

```typescript
import { AsyncStorageService } from '../../common/async-storage/async-storage.service';

const locale    = this.asyncStorage.getLocale();    // 'fr' | 'en' | undefined
const timezone  = this.asyncStorage.getTimezone();  // 'Europe/Paris' | undefined
const userId    = this.asyncStorage.getUserId();    // set by AuthMiddleware
const requestId = this.asyncStorage.getRequestId();
```

## Currency utilities

Located in `src/common/utils/currency.utils.ts` — pure functions, no external dependencies.

```typescript
import {
  formatCurrency,
  toSmallestUnit,
  fromSmallestUnit,
  decimalPlaces,
} from '../../common/utils/currency.utils';

// Format for display
formatCurrency(1234, 'usd', 'en-US')  // '$12.34'
formatCurrency(1234, 'gbp', 'en-GB')  // '£12.34'
formatCurrency(123400, 'ngn', 'en')   // '₦1,234.00'
formatCurrency(1234, 'jpy', 'ja-JP')  // '¥1,234'

// Convert to/from smallest unit
toSmallestUnit(12.34, 'usd')   // 1234
fromSmallestUnit(1234, 'usd')  // 12.34
toSmallestUnit(1234, 'jpy')    // 1234  (zero-decimal — no conversion)

// Decimal places for a currency
decimalPlaces('usd')  // 2
decimalPlaces('jpy')  // 0
```

Zero-decimal currencies (JPY, KRW, etc.) are handled automatically.

## Validation errors

`I18nValidationPipe` + `I18nValidationExceptionFilter` in `main.ts` translate class-validator messages
using the request's active locale. No extra configuration per DTO is required.

```typescript
// main.ts (already configured)
app.useGlobalPipes(new I18nValidationPipe({ whitelist: true, transform: true }));
app.useGlobalFilters(new I18nValidationExceptionFilter());
```

## Adding a new locale

1. Create `src/i18n/<lang>/common.json` (copy from `en/` and translate)
2. Add `'<lang>'` to the `SUPPORTED_LOCALES` array in `async-storage.middleware.ts`
3. Restart the dev server — `nestjs-i18n` watches and hot-reloads translation files
